# O04: incident observability and bounded failure/load evidence

Tested source: `582adc6c9e79566b03125672d20c0af74f5682ed`. Status: Ready for review. Reference work only.

## Implemented scope

The TypeScript gateway emits structured request and dependency/tool spans and
propagates validated custom x-trace-id/x-parent-span-id headers. Python emits
request, embedding, retrieval/pgvector and model-generation spans with matching
trace/parent IDs. The gateway's tool.ingest span measures the real HTTP call to
.NET ingestion; internal .NET phases are not separately instrumented here.
Model spans distinguish deterministic fallback and provider-failure reason codes.
Spans are local JSON metadata, not W3C traceparent/OTLP collector integration or
a deployed tracing backend. Existing Prometheus/Grafana files remain configuration
material; this task does not claim they ran or sent alerts.

Span fields are allowlisted metadata: component, operation, identifiers, duration,
status and safe error type/reason. No prompt, document, embedding vector or provider
error body is added. Invalid parent identifiers are dropped. Unexpected application
errors return a generic HTTP 503 plus trace ID; internal exceptions are recorded
by class rather than exposed with SQL parameters or input content. Unit tests use
private-data canaries to verify this span/HTTP boundary. This is not an audit or
guarantee covering every third-party log or a production security certification.

## Indicators and alert mechanism

User-facing acceptance requires HTTP 200, the fixture fact (30 days), known refund
source ID, explicit fallback mode and matching response trace ID. HTTP status alone
does not define success. Errors are failed acceptance/HTTP/transport observations.
Latency measures client-observed request duration, including failed requests.
Percentiles use nearest rank and are descriptive at this tiny sample size.

Configured demo targets are error rate <=5% and p95 <=1000ms. These are chosen
thresholds, not measured production SLOs or business requirements. A local bounded
window evaluator emits a firing alert when actual observations breach a threshold.
It is a demonstrated local JSON alert, not continuous monitoring, Alertmanager,
PagerDuty/email delivery, burn-rate alerting or an external notification service.
An empty or malformed measurement window cannot report healthy.

## Dated observed results — 17 October 2026

| Window | Requests | Accepted | Errors | p50 ms | p95 ms | Local alert |
|---|---:|---:|---:|---:|---:|---|
| healthy | 12 | 12 | 0 | 8.223 | 23.104 | clear |
| failure | 6 | 0 | 6 | 7.345 | 10.762 | firing |
| recovery | 6 | 6 | 0 | 9.644 | 19.707 | clear |

There were 24 load requests at concurrency <=2, using mock embeddings and
deterministic generation. The controlled failure stopped PostgreSQL; all six
failure-window requests returned HTTP 503. A correlated trace identified a
retrieval.search error in pgvector and its resulting gateway HTTP 503. The
database restarted, all six recovery requests passed acceptance, and the local
alert cleared. A success trace includes a complete parent chain across gateway,
RAG, embedding, retrieval and generation. Actual ingestion tool spans were observed.

This does not measure general capacity, live LLM latency, a production distribution
or sustained availability. The faster failure-window latency is a failed request,
not a performance improvement. B01 remains deferred.

## Reproduction

On a clean Linux checkout with Docker/Compose and ports 3002/3003 free:

```sh
python -m unittest discover -s tests -v
pip install -r services/rag-api/requirements-dev.txt
python -m pytest services/rag-api/tests -q
python tests/integration_o04.py
```

Linux evidence: 11 release/indicator contracts, 3 gateway tests, and 9 RAG tests
passed. Exact gateway npm ci/typecheck/build/test and RAG install/test commands ran
in fresh node:22-alpine / python:3.12-slim containers. The RAG suite emitted one
existing Starlette/AnyIO deprecation warning; it was not suppressed. All runtime
images built and started. No remote Actions run or unchanged evaluator/.NET unit
suite execution is claimed. No pushes or merges were performed.

The load helper records observations and summaries, success/failure span samples,
alert transitions, image/configuration provenance and raw metadata logs under
artifacts/O04-integration. Generated outputs remain ignored, with copies supplied
in the handoff. Documentation/evidence changes after tested source are not reruns.
